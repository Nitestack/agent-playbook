  - **Two separate one-way read-only SSH pull identities from `publisher@<coordinator-host>`:**
    1. `git-ro@<worker>`: `ForceCommand` restricted strictly to read-only `git-upload-pack` under `wt/*` (no shell, no writes).

- **Explicit Same-User Boundary Honesty:**
  - On `<coordinator-host>`, local `<operator>` processes share the single narrow `NOPASSWD` rule `sudo -u publisher /run/current-system/sw/bin/publish-broker`, and local T3 runs as `<operator>` (per NG-01/NG-04 — no custom user-switching launcher). Caller checks (`T3CODE_THREAD_ID`, `worker_thread_id`) and same-host worker isolation (`-C "$WT"` hook) are explicitly documented as **accident/drift/concurrency barriers**, NOT cryptographic authentication between two processes running as `<operator>`.

  - NixOS deploys a **root-owned static template unit `/etc/systemd/system/ci-job@.service`** with hard-coded, non-overridable directives: `DynamicUser=yes`, `PrivateTmp=yes`, `ProtectSystem=strict`, `NoNewPrivileges=yes`, `RuntimeMaxSec=1800`, and a fixed root-owned `ExecStart=/run/current-system/sw/bin/ci-runner %i` (zero persistent writable caches across runs; dependency mirrors mounted strictly read-only).

  - `ci-attest` writes an immutable job manifest (`rust`, `web`, or `fences`, exact `expected_head_oid`, recipe SHA) into a validated read-only spool path keyed by instance ID `^[a-f0-9-]{8,64}$`, starts `ci-job@<id>.service`, observes its exit independently, writes per-job receipts into `/var/lib/ci/receipts/`, and posts the GitHub **Check Run** `local-ci` (§1.3) using its scoped `checks:write` App key only after every required job exits `0`.
- **Crash-Durable, Bootloader-Entry-Verified, Exact-Pre/Post Bundle `infra-switch`:**
  - **Mandatory durability primitive (`atomic_write_durable` & `durable_unlink`):** Every critical state file (`active-review-threads.json`, `/var/lib/infra-switch/{pending,last}-deploy-oid`) uses `write(tmp) → fsync(tmp) → rename(tmp, target) → fsync(parent_dir)`, and every removal uses `unlink(target) → fsync(parent_dir)`.
  - `owner_allowed_signers` lives root-owned at `/etc/<project>/owner_allowed_signers` (`root:root`, `0644`); rollback floor state lives under `/var/lib/infra-switch/` (`root:root`, `0700`). Each NixOS generation embeds its verified commit OID at `/etc/infra-oid`.
  - **Actual Next-Boot Entry Resolution:** `infra-switch` resolves the **actual default boot entry** via `bootctl list --json=short` (reading `isDefault == true` → `<system_path>/etc/infra-oid`; on WSL hosts without systemd-boot, `/nix/var/nix/profiles/system`). If the boot entry cannot be determined unambiguously, `infra-switch` fails closed and retains `pending-deploy-oid` for owner reconciliation.
  - **Exclusive lock + crash reconciliation + exact pre/post write-ahead activation:**
    1. **As `root`, acquire exclusive `flock` `/run/infra-switch.lock`** for the entire verification-through-activation lifecycle (temp bare repo uses unique `mktemp -d /run/infra-verified-XXXXXX.git` under the lock).
    2. **Reconcile prior crash / partial switch first:** If `/var/lib/infra-switch/pending-deploy-oid` exists, check BOTH live `/run/current-system/etc/infra-oid` AND resolved `bootctl` default boot entry OID:

    5. **Capture Pre-State, Extract & Crash-Durable Write-Ahead Activation:**
       - Capture the exact pre-activation triple **`(PRE_LIVE_OID, PRE_BOOT_OID, PRE_PROFILE_OID)`** (abort if any is indeterminable).
       - Extract `/run/infra-verified-<VERIFIED_OID>/` via `git archive "$VERIFIED_OID"`, display diff of `policy.json`, `allowed_signers`, and `ai-hooks/` from that immutable snapshot for human confirmation, **`atomic_write_durable(pending-deploy-oid, $VERIFIED_OID)` BEFORE running `nixos-rebuild switch`**, then run `nixos-rebuild switch --flake "path:/run/infra-verified-<VERIFIED_OID>#$(hostname)"`:
       - **On success (exit 0 AND live OID `== $VERIFIED_OID`):** `atomic_write_durable(last-deployed-oid, $VERIFIED_OID)` **FIRST**, then `durable_unlink(pending-deploy-oid)`.
       - **On any other outcome (non-zero exit, OR exit 0 with live OID `!= $VERIFIED_OID`):** capture post-run `(POST_LIVE_OID, POST_BOOT_OID, POST_PROFILE_OID)`:
         - **ONLY if non-zero exit AND ALL THREE are determinable AND exactly equal their pre-activation values (`POST_LIVE_OID == PRE_LIVE_OID && POST_BOOT_OID == PRE_BOOT_OID && POST_PROFILE_OID == PRE_PROFILE_OID`):** `durable_unlink(pending-deploy-oid)` before releasing the lock.
         - **Otherwise** (exit 0 mismatch, any pointer indeterminable, moved to `$VERIFIED_OID`, OR moved to any third OID `C`): **retain `pending-deploy-oid`** for reconciliation.
  - **Everyday DX:** FIDO2 `sk-` (`verify-required`) on `<coordinator-host>` is the fast 1-second everyday signing path; offline device key serves as backup.

### 2.1 Secret 256-Bit Nonce + Per-Call `PreToolUse` Enforcement on BOTH Claude & Codex (Closes Sol #<n>)
- **Single ledger host:** `<coordinator-host>` (`/var/lib/orch/state/`, owned by `publisher`). Reviewers run strictly read-only and write **nothing**.
- **Two exact, provable invariants enforced identically on BOTH Claude Code AND Codex CLI (honest about non-atomic sends & non-retroactive authorization):**
  - **(I1 — Per-call gating of subsequent tool calls on BOTH providers):** Before authorizing any tool call in any T3 scratch thread, the `PreToolUse` hook (deployed in `~/.claude/settings.json` for Claude AND `$CODEX_HOME/hooks.json` for Codex — both inherit `T3CODE_THREAD_ID`, verified in `ClaudeAdapterV2.ts:1733` & `CodexAdapterV2.ts:1744`) verifies BOTH `active-review-threads.json` AND the live thread/transcript state: authorizing ONLY when `user_message_count == 1` AND `sha256(first_user_message) == expected_brief_sha256` (embedding the secret 256-bit broker nonce) AND (where exposed) `active_run_id == canonical_run_id`. Any second user message accepted before the next tool authorization check immediately causes **every subsequent tool call — including an otherwise permitted snapshot read — to be denied fail-closed on both Claude and Codex** (this gates subsequent calls cleanly without claiming to retroactively revoke a tool call already authorized and in progress).
  - **(I2 — Zero publishable tainted evidence):** `ingest-review` verifies `runCount == 1 && runId == canonical_run_id && messageId == canonical_message_id && user_message_count == 1 && sha256(first_user_message) == expected_brief_sha256`, unconditionally rejecting any tainted thread as unpublishable.
- **Execution sequence:**
  1. `publish-broker request-review` generates a fresh 256-bit CSPRNG `nonce` (kept strictly inside `publisher`'s `0600` state — never written in plaintext to `active-review-threads.json`), materializes the `.git`-free, OS-read-only snapshot at `/run/review-ro/<reservation_id>` (`chmod -R a-w`, owned by `publisher`, mode `0555`/`0444`) containing exact `candidate_oid` tree PLUS `REVIEW_PR.diff`, `REVIEW_RANGE_DIFF.txt`, `REVIEW_COMMITS.txt`, and `REVIEW_CHANGED_FILES.txt`, and computes `rendered_brief` (including a 1-line note to retry once if an initial read is transiently denied during startup registration) + `expected_brief_sha256 = sha256(rendered_brief)`.

  3. **Pre-send virgin-thread check:** Broker verifies `t3_thread_read(view: "activity")` reports `runCount == 0 && itemCount == 0`. If tainted, broker interrupts (`t3_thread_interrupt`), never registers it, and starts a fresh reservation.

     - While unregistered (fail-closed hook denies all tools), broker calls `t3_thread_send(threadId: reviewer_thread_id, mode: "queue", clientRequestId: "review-send:<reservation_id>", message: <rendered_brief>)`, receiving T3's authoritative `canonical_run_id` and `canonical_message_id`.

     - Broker persists `{ reviewer_thread_id, canonical_run_id, canonical_message_id, expected_brief_sha256, snapshot_root }` via **`atomic_write_durable`** (`write → fsync(tmp) → rename → fsync(/var/lib/orch/state)`) into `active-review-threads.json`.
  5. **Provider-specific read-only containment + shared I1 per-call turn check (`#<n>` — Closes Sol #<n>):**

## 3. Drain-or-Cancel Shift Rotation & Multi-Provider Guardrails
