Why teams add it to their repos

Prompts alone decay over a long session. Each part of the kit targets a real failure mode seen in multi-agent runs.

Long orchestrator threads start coding

After a few compactions, a coordinator forgets its role and starts editing files or debugging tests inline. Fix: one-command in-place shift renewal (playbook-registry.sh renew) plus a coordinator guard that blocks repo writes and builds.

Workers wander outside their worktree

A parallel agent touches another ticket's files or pushes straight to main. Fix: worker-guard.sh confines writes to the ticket's worktree and refuses protected branches even if misbound.

Reviewers agree with the author's summary

Handing a reviewer the author's transcript biases the verdict. Fix: blind-review runs in a fresh read-only context over a blob-exact, .git-free snapshot of one exact commit SHA.

Rebases silently invalidate approvals

Clicking "Rebase and merge" creates unreviewed SHAs, while re-reviewing everything stalls the queue. Fix: exact-SHA fast-forward publishing paired with a 3-outcome rebase classifier.

Not a sandbox and not a daemon: guards stop well-meaning agents from drifting, and Tier 2 adds hard credential separation when several hosts publish.

Three tiers, adopted in order

Move to the next tier only when its trigger is real. Each tier keeps everything below it.

  1. Tier 0: solo or quick repo

    Applies to scripts, experiments and configuration repos.

    Turns on: a short AGENTS.md with verifiable commands, a CLAUDE.md that points to it, and repo-scoped stack skills.

  2. Tier 1: active product repo

    Trigger: two or more agents work in parallel, UI changes need browser checks, or a defect escaped review.

    Adds: a shift-based orchestrator with in-place renewal, coordinator, worker and reviewer guards, blind-review, and browser-verify.

  3. Tier 2: multi-host publishing

    Trigger: several hosts write code that lands on a protected branch.

    Adds: brokered publishing (workers hold no push credentials), an owner gate for policy paths, and per-host admission control.

The bootstrap-repo skill reads only the templates for the tier it is applying.

One shift runs one milestone slice

An orchestrator is a dispatcher: it splits and routes work. One thread equals one shift, and a shift renews proactively so context never rots.

A shift renews or rotates when a trigger fires

  • compactions >= 2
  • dispatches_in_shift >= 40
  • shift_age >= 6h (playbook-registry.sh status reports ROTATE_DUE)
  • the milestone slice is complete

In-place renewal first, fenced rotation as fallback

  1. Renew in place (default). Run playbook-registry.sh renew and refresh the thread in a fresh context (freshContext or /clear). The thread ID, guard, watches, heartbeat and live child callbacks stay intact.
  2. Freeze and drain (fallback). When the thread ID must change, run playbook-registry.sh drain <marker>, wait up to 15 minutes, cancel what is left and record --cancelled. After two forced rotations, escalate to the owner.
  3. Bind an idle candidate. Launch the successor idle, bind it with bind-candidate (dispatch disabled), and send the compact handoff packet.
  4. Atomic takeover. After the successor recovers state and attaches its watches, takeover promotes it and sets the predecessor to state: "retired" so its guard keeps running. On failure before takeover, abort resumes the shift.

Each wakeup runs one pass, then ends the turn

  1. Verify completions by exact PR, branch and 40-char SHA. Never claim done from memory.
  2. Advance PRs: build a blob-exact review snapshot (review snapshot) for blind-review, route fixes to rebase-and-fix, hand approved green work to the operator or publish-pr.
  3. Refill slots immediately with the next ready ticket using ticket-implement.
  4. Hygiene & check rotation: settle finished children, route safe-cleanup for confirmed merges, and check playbook-registry.sh status for ROTATE_DUE.
  5. Stop the turn. Never wait in a loop; children, watches and the 20-minute heartbeat wake the shift.

From one issue to a merged PR

Each stage hands over an exact tuple: a PR, a base commit and a head commit. A verdict counts only for the tuple it names.

  1. ticket-implementone issue, one PR, exact SHAs (or ALREADY_SATISFIED)
  2. blind-reviewfresh, read-only, one immutable snapshot
  3. publish-prapproval evidence and green CI: exact-SHA fast-forward
  4. safe-cleanupexact-tip verified, merged work only

REQUEST_CHANGES from blind-review, or NEEDS_REBASE from publish-pr:

  1. rebase-and-fixFULL-first 3-outcome classifier, push with a lease (Tier 2: hand off to the publisher)
  2. blind-reviewthe review the classification asks for, on the new tuple
  • Publishing never rewrites reviewed commits. publish-pr pushes with a lease on the expected base and confirms MERGED at the exact head.
  • A moved base is not rebased during publish. The PR routes to rebase-and-fix and the rest of the queue keeps moving.

Ten workflow skills, Markdown only

Every skill is a single lean SKILL.md written in tool-neutral English. Filter by role or open any skill straight on GitHub.

10 of 10 skills shown

orchestrate

Run or renew an orchestrator shift for one milestone slice: unified startup, in-place renewal, fenced rotation fallback, and non-blocking routing.

Use when starting a shift, renewing context, or taking over a rotated shift.

ticket-implement

Implement one issue end to end in an isolated worktree: red-green TDD, foreground gates, signed linear commits, exact-SHA PR or ALREADY_SATISFIED.

Use when the task is a single issue number, from pre-flight to pull request.

bootstrap-repo

Equip a new or existing repo tier by tier using the templates in references/, plus repo-scoped stack skills.

Use when adding AGENTS.md, REVIEW.md, or docs/orchestration.md.

rebase-and-fix

Apply review fixes, resolve conflicts, renumber migrations and rebase onto a moved base with the FULL-first 3-outcome classifier.

Use when a PR is REQUEST_CHANGES, reports NEEDS_REBASE, or conflicts.

blind-review

Anti-anchored review of one exact (PR, base, head) tuple from a fresh read-only context over a blob-exact, .git-free snapshot.

Use when a PR is green and needs a verdict, or a new head needs re-review.

council-review

Cold, independent reviewers discuss on a shared temporary board (blind R1 → all-to-all R2 → consensus R3) and converge with evidence.

Use when deciding major architecture, security boundary or policy shifts.

browser-verify

Verify UI changes in a real browser against the exact candidate build SHA: routes, console errors, network failures, focus and empty states.

Use when a task changes web UI, layout, routing or client-side API behavior.

publish-pr

Land one approved, green PR by exact-SHA compare-and-swap fast-forward with intent reconciliation and exact-tuple verification.

Use when a PR is approved and green, or stopped on a moved default branch.

safe-cleanup

Inventory and remove stale worktrees, merged branches and build caches with exact-tip verification, never touching unmerged or live work.

Use when disk space is low, worktrees pile up, or PRs have merged.

session-miner

Mine session transcripts, CI failures and review rounds for recurring friction and turn each root cause into a sanitized mechanical fix.

Use when a milestone ends or the same failure keeps coming back.

Guard hooks: three roles, three sets of limits

Each guard is a PreToolUse hook. Inactive threads exit 0 before reading stdin; active threads get checked and receive actionable reasons on exit 2.

What each guard allows and denies
RoleAllowsDeniesActive when
Coordinator Read tools, read-only git and gh, gh issue create/comment, GET-only gh api, publish broker (status only while draining), playbook-registry.sh except removing itself or a retired entry Repo writes, builds, tests, mutating git, merges by CLI or forge tool, wait loops, dispatches while draining or as a candidate, and everything except teardown/reads once retired Thread id (PLAYBOOK_THREAD_ID, else T3CODE_THREAD_ID) is in the coordinator registry
Worker Writes inside its own worktree; pushes only to PLAYBOOK_WORKER_BRANCH (or its registered branch) when set Writes outside the worktree; pushes to protected branches (PLAYBOOK_PROTECTED_BRANCHES, default main master develop), even if bound to one PLAYBOOK_WORKER_WORKTREE is set, or the thread id is listed in the worker registry
Reviewer Claude Code's Read, Grep and Glob inside the review snapshot (including base/ with --with-base). Codex reviewers use Codex's read-only sandbox. Bash, write tools, MCP tools, web access, sub-agents, paths or symlinks escaping the snapshot Thread id is in the review registry with a snapshot_root
  1. A tool call arrives.
  2. Not active for this thread? Exit 0 at once: allowed, stdin never read.
  3. Role & lifecycle rules check the call.
  4. Allowed: exit 0. Denied: reason printed, exit 2.

Manual setup: Nix or symlinks

Prefer wiring it up yourself instead of asking your agent? Nix is optional, skills are Markdown, and hooks need only bash 4+, jq, git and GNU coreutils.

With Nix and Home Manager

Add the playbook as a non-flake input, pass it to Home Manager, and link every skill:

inputs.agent-playbook = {
  url = "github:Nitestack/agent-playbook";
  flake = false;
};

# Home Manager module:
{ lib, agent-playbook, ... }:
let skills = lib.filterAttrs (_: t: t == "directory")
  (builtins.readDir "${agent-playbook}/skills");
in {
  home.file = lib.mapAttrs' (name: _:
    lib.nameValuePair ".claude/skills/${name}"
      { source = "${agent-playbook}/skills/${name}"; }) skills;
}

CI keeps skills/ Markdown-only, so this deploys no scripts. Hook commands point at ${agent-playbook}/hooks/.

Without Nix

Symlink the skills into your agent's skill directory. Reruns replace only links pointing into this checkout and skip real files or foreign links.

src_root=$(readlink -f /path/to/agent-playbook)
dest=~/.claude/skills
mkdir -p "$dest"
for s in "$src_root"/skills/*/; do
  s=${s%/}; name=$(basename "$s"); link=$dest/$name
  if [ -L "$link" ]; then
    case $(readlink -f "$link") in
      "$src_root"/*) ln -sfn "$s" "$link" ;;
      *) echo "skip $name: foreign link" ;;
    esac
  elif [ -e "$link" ]; then
    echo "skip $name: exists"
  else
    ln -s "$s" "$link"
  fi
done

Register the three guards in ~/.claude/settings.json or ~/.codex/hooks.json; the README has both snippets.

Registry CLI quick reference

Check shift age, bump generation in place, then refresh context (freshContext or /clear) without draining healthy workers.

hooks/playbook-registry.sh coordinator add <thread-id> [slice]
hooks/playbook-registry.sh status
hooks/playbook-registry.sh renew

Fenced new-thread fallback: freeze dispatches, bind an idle candidate, atomically promote & retire predecessor, or abort before takeover.

hooks/playbook-registry.sh drain <handoff-marker> [--cancelled]
hooks/playbook-registry.sh bind-candidate <successor-thread-id>
hooks/playbook-registry.sh takeover <predecessor-thread-id> <handoff-marker>
hooks/playbook-registry.sh abort <handoff-marker>

Build a blob-exact, read-only, .git-free snapshot (optionally bundling base/ and fetching a remote ref), then tear it down after the verdict.

hooks/playbook-registry.sh review snapshot --with-base <rev-tid> <repo> <base-oid> <head-oid>
hooks/playbook-registry.sh review remove <rev-tid>

Fallback activation for idle-launched worker threads when environment variables cannot be injected at launch.

hooks/playbook-registry.sh worker add <worker-tid> <worktree> [branch]
hooks/playbook-registry.sh worker remove <worker-tid>
hooks/playbook-registry.sh show worker

The research archive, R1 to R15

The decisions behind the blueprint came from a fifteen-round council. Two reviewer panels scored each round for developer and agent experience, out of 10. The archive is frozen: grep the section you need, and do not read a file in full.

  1. R1 to R2

    Live audits: the skill catalog, Git 2.56 patch-id, and a publish-script bug audit (P1 to P12).

    DX/AX: 7.5/7.0 & 7.0/6.5

  2. R3 to R6

    Brokered publishing with no worker push tokens, the policy-path owner gate, and a bundle-based host switch.

    8.5/8.5 & 8.5/7.0

  3. R7 to R9

    A static CI unit, Check Runs provenance, verified OpenSSH 10.6p1 and ast-grep 0.51.2 behavior, an isolated fences job.

    8.9/8.6 & 8.5/7.8

  4. R10 to R14

    Diminishing returns: registration race conditions and multi-pointer crash states.

    9.6/9.6 & 9.3/8.9

  5. R15

    The judge trimmed R10 to R15 over-engineering. The lean plan scored 9.4 DX and 9.3 AX.

    9.6/9.6 & 9.5/9.1

Kept from R1 to R9

  • The orchestrator failure mode and the shift model.
  • Skill pruning from 87 to 28, and supply-chain hygiene for external packs.
  • Credential and host boundaries: no worker push credentials, one serialized publish broker.
  • Verified tooling bugs, such as patch-id --verbatim over --stable.
  • A bundle-based, root-isolated host switch.
  • Reviewer independence means a fresh context, not a second vendor.

Trimmed in R10 to R15

  • Stdin injection into read-only reviewers, and transcript parsing on every read.
  • A distributed crash write-ahead log for the host switch.
  • A local attested CI subsystem, built to work around paused hosted CI minutes.

Adopt it in a new repo

Start at Tier 0. Copy the templates, fill every blank with the repo's real commands, and keep only the rules the code cannot show. Or ask an agent to run bootstrap-repo.

Tier 0: day zero

cp /path/to/agent-playbook/skills/bootstrap-repo/references/AGENTS.template.md AGENTS.md
  • Fill in format, lint, test and gate commands in AGENTS.md.
  • CLAUDE.md holds one line: @AGENTS.md.
  • Copy the issue and pull request templates into .github/.
  • Write a fail-closed CI with actions pinned to full SHAs.

Tier 1: parallel agents

  • Add REVIEW.md from its template. Reviewers are fresh and read-only.
  • Add docs/orchestration.md with Tier 1 sections only.
  • Turn on the coordinator, worker and reviewer guards.
  • For a UI repo, run one candidate-build browser check.

Tier 2: several hosts publish

  • Workers hold no push credentials; one publisher pushes under one lock.
  • Policy paths require the owner's signed approval on the exact head.
  • Set host caps with hysteresis for memory, pressure and free disk.

Verify every file you add against the repo's own CI before you call the bootstrap done.

Adopt the tiers in order, and move up only when the trigger is real.
